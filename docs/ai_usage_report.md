# 5. AI 활용범위 및 주요 검토 과정

2026 DATA·AI 분석 경진대회 문제해결 부문 · 과제 7: 댐·하천 유해남조류(녹조) 7일 예측 · 팀 19일의 월요일

## 5.1 활용 도구

Anthropic의 Claude Code(코드 에이전트 환경, 클라우드 세션과 데스크톱 앱)를 사용하였다. 모델: Claude Fable 5.1. 별도의 외부 AI 서비스나 API는 결과물 실행에 필요하지 않다.

## 5.2 활용 단계

문제 분석, 데이터 처리, 모델 설계, 코드 작성, 실험, 결과 분석, 문서 작성의 일곱 단계에서 보조 수단으로 활용하였다.

- 문제 분석: 문제해결 부문 일곱 개 과제를 데이터 가용성·평가 지표·난이도로 비교한 표를 작성하는 데 활용하였고(docs/task_candidates.md), 과제 선택은 팀이 하였다.

- 데이터 처리: 조류경보제 측정값에 기상·댐·하천 자료를 결합하는 코드 작성(src/data_ai/bloom.py), 외부 자료 수집 스크립트 작성(scripts/fetch_wamis.py).

- 모델 설계·코드 작성·실험: 학습·검증 스크립트, 변형 실험을 같은 조건에서 비교하는 스크립트 작성과 실행(scripts/train.py, scripts/experiments\*.py).

- 결과 분석·문서 작성: 실험 표 정리, 방법 설명서와 모델링 기록 초안.

## 5.3 주요 활용 내용

1.  **자료 결합 코드**: 지점별 최근접 기상관측소와 상류 다목적댐 자료를 기준일 포함 과거 7·14·28일 창으로 집계해 붙이는 코드. 기준일 이후 정보가 섞이지 않도록 과거 방향 집계(rolling, merge_asof backward)만 쓴다.

2.  **모델링·평가 코드**: log10(세포수+1) 목표의 LightGBM 회귀, 공식 분할(학습 ≤2024 / 검증 2025)과 연도별 롤링 검증, 공식 지표(log10 RMSE·MAE, R², NSE, F1@10,000) 계산.

3.  **실험 정리**: 변형 실험 30여 개와 외부 자료 4종을 같은 분할·같은 입력에서 비교하는 스크립트와 결과 표(reports/experiments.csv, experiments_round3.csv, experiments_round4.csv, docs/modeling_notes.md).

4.  **외부 자료 수집 도구**: WAMIS OpenAPI 수집 스크립트. 수집 자체는 팀원 PC에서 실행하였다.

## 5.4 참가자 주요 기여 및 검증

- **과제 선택과 범위 결정**: 일곱 과제 중 녹조 예측을 선택하고, 발표 자료 대신 모델·설명서에 집중하기로 결정하였다(10-19~10-22).

- **외부 자료 확보**: DataON 댐유역 하천 수위(6개 파일)와 다목적댐 운영자료(2010~2026)를 팀장이 내려받았고, WAMIS 본류 수위는 팀원 PC에서 수집 스크립트를 실행해 받았으며(수집 중 API 경로 오류·연결 끊김 문제를 팀원이 보고해 스크립트를 수정), 국립환경과학원 수질자동측정망 자료(57,530행)는 팀원이 수집해 독립적으로 검증하였다(10-21~10-26).

- **지점과 상류 댐의 대응 관계 결정**: 제공 자료에 대응표가 없어 수계 지리를 근거로 정하였고, 검토 과정에서 해평 지점에 김천부항댐을 추가하였다. 근거는 configs/bloom.yaml 주석에 남겼다(10-20).

- **정답 누수 사고의 발견과 차단**: 변형 실험 초기에 자체 채점용 정답 열이 입력에 섞여 R² 0.9라는 비현실적 결과가 나왔다. AI 도구가 이 결과의 이상을 먼저 짚었고, 팀원이 이를 보고 직접 확인하여 원인을 추적하였다. 이후 입력 열 선택을 제외 방식에서 허용 목록 방식으로 바꾸었으며, 정답 관련 열이 섞이면 실행이 중단되는 단위 테스트를 추가하였다(docs/modeling_notes.md 3장).

- **모델 선택 기준 설정**: 2026년 자체 채점값(번들 실측)은 참고로만 기록하고 선택에는 쓰지 않는다는 규칙을 정했다. 시드 3개 편차(0.006)를 잡음 기준으로 두고, 그 두 배 이상 일관되게 좋아지는 변경만 채택하였다.

- **팀 내 제안의 직접 검증**: 팀원이 받은 조언(XGBoost·CatBoost 앙상블, 지점별 원핫 인코딩)을 같은 입력·같은 검증 세트로 돌려 효과 없음을 확인하였다(10-23). 팀원이 독립적으로 만든 모델의 제출 파일을 같은 기준으로 채점해 비교하였다(10-22).

- **R² 정의 확인**: 대회의 R²가 결정계수인지 상관계수의 제곱인지 불분명해 두 값을 함께 기록하며 운영사무국에 문의하였다. 출제기관은 R²가 관측값과 예측값의 피어슨 상관계수를 제곱한 값이며 원 단위로 계산한다고 답하였고, 1 − SSE/SST는 NSE와 같은 값이 되므로 R²에 쓰지 않는다고 안내하였다. 이 정의를 설명서에 명시하였다.

- **과제 설명문 요구사항 대조**: 팀원이 과제 설명문의 "융합 난제"(누적 강우, 체류시간 대리변수, 이동평균 수온)와 "결측 대체 전략 평가" 항목이 실제로 반영됐는지 확인을 요청해, 각 항목이 어느 코드·피처로 구현됐는지 점검하였다(10-23).

- **대회 Q&A 반영**: 모델 확정(10-26) 뒤 올라온 Q&A ⑤(최종 모델 학습에는 학습용 조합만 사용, 2025년 자료는 모델 선택과 하이퍼파라미터 결정에만 사용)를 설명서와 대조하는 검토에서, 최종 모델이 검증 2025 자료까지 합쳐(2,566행) 재학습되고 있음이 드러났다. 학습 자료(≤2024, 2,310행)만으로 학습하도록 바꾸었고, 반복 수는 검증에서 정한 146회를 그대로 쓰되 ×1.1 보정은 없앴으며 결측 통계와 범주 목록도 학습 행에서만 계산한다. 검증 2025와 롤링 점수는 원래 ≤2024 학습 값이라 그대로이고 모델 파일과 제출 파일이 바뀌었다(11-05). 같은 검토에서 모델링 기록의 채택 문장에 참고용 2026 채점이 언급된 것을 찾아 정정하였다.

- **재현성 확인**: 위 변경 후 make train 재실행, 저장된 모델로 추론, 노트북 전체 재실행이 모두 제출 파일 124행과 일치하였다(11-05). 같은 날 팀원 PC(Windows 11 Pro, Python 3.14.6)에서 새 제출 파일을 내려받아(git pull) predict.py를 실행한 결과 "평가 조합 124건 중 불일치 0건"을 출력하였다. 이전 제출 파일은 10-26, 11-03에 같은 방식으로 확인하였다.

## 5.6 최종 선택 이유

**같은 수계 상류 지점의 기준일 이전 최근 세포수를 입력에 추가하고, LightGBM에 extra_trees를 적용**한 것만 채택하였다. (4차 실험, 10-23).

- 근거: 낙동강 본류에서 바로 상류 지점의 최근 세포수는 하류의 수일 후 상태에 대한 선행 신호가 된다(7일 뒤 세포수와 상관 0.75). extra_trees는 분할점을 무작위로 골라 트리 간 상관을 낮추며, 학습 표본 약 2,300행에서 과적합을 완화한다.

- 검증: 네 검증 구간(2022~2025) 평균 rmse_log10 0.784 → 0.772, 시드 3개 모두 개선, 개선 폭 0.012는 시드 편차 0.006의 두 배. 채택 기준은 네 검증 구간 평균과 시드 간 일관성이며, 2026년 자체 채점값은 선택에 쓰지 않았다. 공식 검증 2025만 보면 차이가 없었으나 롤링 세 해가 좋아져 채택하였다.

- 결측 대체: 세 전략의 차이(0.70~0.72)가 유의하지 않아 검증 오차가 가장 낮은 전략을 자동 선택하게 하였다(현재 직전 측정값 대체 + 결측 표시).

- 단순성 유지: 앙상블·2단계 모델·지점별 모델은 복잡도를 높이면서 개선이 없어 단일 LightGBM을 유지하였다. 재현성과 설명 가능성(피처 중요도, SHAP)도 단일 모델이 유리하다.

- 최종 성능: 검증 2025 rmse_log10 0.704, F1@10,000 0.651. persistence(0.883) 대비 오차 20% 감소.
