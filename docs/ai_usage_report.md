# 5. AI 활용범위 및 주요 검토 과정

> 근거: 저장소 커밋 이력(2026-10-19 ~ 11-03), `docs/modeling_notes.md`, `reports/experiments*.csv`, `docs/method_description.md`. 아래 수치는 모두 이 기록에서 가져왔다. `[확인 필요]`로 표시한 부분은 기록만으로 확인되지 않아 팀이 채워야 한다.

## 5.1 활용 도구

Anthropic의 Claude Code(코드 에이전트 환경, 클라우드 세션과 데스크톱 앱)를 사용하였다. 모델: [확인 필요: 세션에서 확인한 모델명 기입]. 별도의 외부 AI 서비스나 API는 결과물 실행에 필요하지 않다.

## 5.2 활용 단계

문제 분석, 데이터 처리, 모델 설계, 코드 작성, 실험, 결과 분석, 문서 작성의 일곱 단계에서 보조 수단으로 활용하였다.

- 문제 분석: 문제해결 부문 일곱 개 과제를 데이터 가용성·평가 지표·난이도로 비교한 표를 작성하는 데 활용하였고(`docs/task_candidates.md`), 과제 선택은 팀이 하였다.
- 데이터 처리: 조류경보제 측정값에 기상·댐·하천 자료를 결합하는 코드 작성(`src/data_ai/bloom.py`), 외부 자료 수집 스크립트 작성(`scripts/fetch_wamis.py`).
- 모델 설계·코드 작성·실험: 학습·검증 스크립트, 변형 실험을 같은 조건에서 비교하는 스크립트 작성과 실행(`scripts/train.py`, `scripts/experiments*.py`).
- 결과 분석·문서 작성: 실험 표 정리, 방법 설명서와 모델링 기록 초안.

## 5.3 주요 활용 내용

1. **자료 결합 코드**: 지점별 최근접 기상관측소와 상류 다목적댐 자료를 기준일 포함 과거 7·14·28일 창으로 집계해 붙이는 코드. 기준일 이후 정보가 섞이지 않도록 과거 방향 집계(`rolling`, `merge_asof backward`)만 쓴다.
2. **모델링·평가 코드**: log10(세포수+1) 목표의 LightGBM 회귀, 공식 분할(학습 ≤2024 / 검증 2025)과 연도별 롤링 검증, 공식 지표(log10 RMSE·MAE, R², NSE, F1@10,000) 계산.
3. **실험 정리**: 변형 실험 30여 개와 외부 자료 5종을 같은 분할·같은 입력에서 비교하는 스크립트와 결과 표(`reports/experiments.csv`, `experiments_round3.csv`, `experiments_round4.csv`, `docs/modeling_notes.md`).
4. **외부 자료 수집 도구**: WAMIS OpenAPI 수집 스크립트. 수집 자체는 팀원 PC에서 실행하였다.

## 5.4 참가자 주요 기여 및 검증

기록으로 확인되는 항목:

- **과제 선택과 범위 결정**: 일곱 과제 중 녹조 예측을 선택하고, 발표 자료 대신 모델·설명서에 집중하기로 결정하였다(10-19~10-22).
- **외부 자료 확보**: DataON 댐유역 하천 수위(6개 파일)와 다목적댐 운영자료(2010~2026)를 팀장이 내려받았고, WAMIS 본류 수위는 팀원 PC에서 수집 스크립트를 실행해 받았으며(수집 중 API 경로 오류·연결 끊김 문제를 팀원이 보고해 스크립트를 수정), 국립환경과학원 수질자동측정망 자료(57,530행)는 팀원이 수집해 독립적으로 검증하였다(10-21~10-26).
- **지점과 상류 댐의 대응 관계 결정**: 제공 자료에 대응표가 없어 수계 지리를 근거로 정하였고, 검토 과정에서 해평 지점에 김천부항댐을 추가하였다. 근거는 `configs/bloom.yaml` 주석에 남겼다(10-20).
- **정답 누수 사고의 발견과 차단**: 변형 실험 초기에 자체 채점용 정답 열이 입력에 섞여 R² 0.9라는 비현실적 결과가 나왔다. 이를 의심해 원인을 추적하고, 입력 열 선택을 제외 방식에서 허용 목록 방식으로 바꾸었으며, 정답 관련 열이 섞이면 실행이 중단되는 단위 테스트를 추가하였다(`docs/modeling_notes.md` 3장). [확인 필요: 처음 의심한 사람이 팀원인지 AI 도구인지]
- **모델 선택 기준 설정**: 2026년 자체 채점값(번들 실측)은 참고로만 기록하고 선택에는 쓰지 않는다는 규칙을 정했다. 시드 3개 편차(0.006)를 잡음 기준으로 두고, 그 두 배 이상 일관되게 좋아지는 변경만 채택하였다.
- **팀 내 제안의 직접 검증**: 팀원이 받은 조언(XGBoost·CatBoost 앙상블, 지점별 원핫 인코딩)을 같은 입력·같은 검증 세트로 돌려 효과 없음을 확인하였다(10-23). 팀원이 독립적으로 만든 모델의 제출 파일을 같은 기준으로 채점해 비교하였다(10-22).
- **R² 정의 확인**: 대회의 R²가 결정계수인지 상관계수의 제곱인지 불분명해 두 값을 함께 기록하고 설명서에 정의를 명시하였다. [확인 필요: 주최 측 Q&A에 실제로 문의했는지, 답변 내용]
- **과제 설명문 요구사항 대조**: 팀원이 과제 설명문의 "융합 난제"(누적 강우, 체류시간 대리변수, 이동평균 수온)와 "결측 대체 전략 평가" 항목이 실제로 반영됐는지 확인을 요청해, 각 항목이 어느 코드·피처로 구현됐는지 점검하였다(10-23).
- **재현성 확인**: 저장소를 새로 내려받아 처음부터 실행한 결과 제출 파일 124행이 모두 일치하였고, 저장된 모델로 추론한 값도 일치하였다(10-26, 11-03). [확인 필요: 다른 팀원 PC에서의 재현 확인 여부]

**예상과 다른 결과**

- 과제 설명문이 강조한 체류시간 대리변수(저수량/방류량)와 하천 수위는 모델 중요도가 낮았다. 7일 뒤 봉우리를 결정하는 정보는 기준일 세포수와 수온·기온 추세에 거의 다 들어 있었다.
- 과제 목표(R² 0.6, NSE 0.5)를 달성하지 못했다(검증 2025 R² 0.17, 롤링 2024 0.37). 원 단위 지표는 수십만 cells/mL 봉우리 몇 개가 좌우하고, 로그 공간 모델은 봉우리를 과소예측한다. 로그 지표와 원 단위 지표는 상충해 둘을 동시에 올리는 변형을 찾지 못했다.

## 5.6 최종 선택 이유

채택한 변경은 하나다: **같은 수계 상류 지점의 기준일 이전 최근 세포수를 입력에 추가하고, LightGBM에 extra_trees를 적용**한 것(4차 실험, 10-23).

- 근거: 낙동강 본류는 해평 → 강정·고령 → 칠서 → 물금·매리 순으로 흐르므로 바로 상류 지점의 최근 세포수는 하류의 수일 후 상태에 대한 선행 신호가 된다(7일 뒤 세포수와 상관 0.75). extra_trees는 분할점을 무작위로 골라 트리 간 상관을 낮추며, 학습 표본 약 2,300행에서 과적합을 완화한다.
- 검증: 네 검증 구간(2022~2025) 평균 rmse_log10 0.784 → 0.772, 시드 3개 모두 개선, 개선 폭 0.012는 시드 편차 0.006의 두 배. 공식 검증 2025만 보면 차이가 없었으나 롤링 세 해와 참고용 2026 채점이 모두 좋아져 채택하였다.
- 결측 대체: 세 전략의 차이(0.70~0.72)가 유의하지 않아 검증 오차가 가장 낮은 전략을 자동 선택하게 하였다(현재 직전 측정값 대체 + 결측 표시).
- 단순성 유지: 앙상블·2단계 모델·지점별 모델은 복잡도를 높이면서 개선이 없어 단일 LightGBM을 유지하였다. 재현성과 설명 가능성(피처 중요도, SHAP)도 단일 모델이 유리하다.
- 최종 성능: 검증 2025 rmse_log10 0.704, F1@10,000 0.651. persistence(0.883) 대비 오차 20% 감소.

※ 모든 프롬프트와 AI와의 전체 대화 내용은 제출하지 않았으며, 최종 결과물과 주요 의사결정에 영향을 준 활용 내용을 중심으로 작성하였다.
